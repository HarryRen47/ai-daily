Anthropic 发布 Claude Fable 5.2 与 Mythos 5.2：标准价降至 $8 / $40，FrontierCode 2.0 最高 49.1%

11-09 北京时间本日头条 · 热榜 #1 · 官博标注 Nov 9；官方 X 主帖北京时间 11-10 02:57，略出窗口独立来源 3 家

Claude Fable 5.2 与 Mythos 5.2 发布封面（图片来源：Anthropic Newsroom）

介绍

Anthropic 发布 Claude Fable 5.2 与 Claude Mythos 5.2：两者为同一底层模型，主打更难的技术任务，在编码、推理与视觉上有提升。Fable 面向所有用户，Mythos 去掉部分安全限制，需通过 Cyber 或 Life Sciences Verification Program 申请。官博给出的标准价为每百万输入 $8、输出 $40（前代 Fable 5.1 为 $10 / $50）；可选 Fast 模式最高约 2.5 倍出词速度，价格为 $16 / $80。官方称输出最多比 5.1 快 30%。Fable 5.2 已在所有付费方案、Claude Platform 及主要云平台上线。

为什么重要

这是当天分量最重的模型发布：把「日常主力」和「最难技术活」进一步拆开——官方仍建议多数编码与知识工作从 Opus 5.5 起步，把 Fable / Mythos 留给更开放、更长周期的任务。

要点
  • 官方基准（最高可用 effort，除非另注）：FrontierCode 2.0 上 Fable 5.2 为 49.1%（Xhigh），高于 Fable 5.1 的 32.4%、Opus 5.5 的 45.5%、GPT-6 Astra 的 42.8%；官方称 High effort 时约与 Opus 5.5 Max（45.3% vs 45.5%）持平，单任务成本约一半。AutomationBench 51.4%，Terminal-Bench-Science 0.1 上 Fable 74.6%、Mythos 75.3%。
  • 演示任务（官方口径）：预发布测试中，模型从一段提示出发设计了三款可工作的电子设备；1000 个 Fable 5.2 智能体用 30 小时完成费马大定理的形式化证明（同等设置下 Opus 5.5 在 18 小时内完成约 26%，30 小时后几乎不再推进）；并解决了两个与黑洞相关的理论物理开放问题，其中一项被官方称为搁置 23 年的计算。
  • 怎么用：官方建议多数日常任务仍从 Opus 5.5 的 medium effort 起步，再按任务难度上调到 Fable / Mythos 或下调到 Sonnet / Haiku；Fable 也可做 Advisor 或 Orchestrator。第三方凌晨评测（如 Artificial Analysis、Arena 登顶分数）发生在北京时间 11-10 凌晨，不写入本期正文。

Google 一年内推出四款第八代 TPU：新增 8i Max 与 8tx

11-09 北京时间热榜 #3 · 官博 Nov 9 · @Google 北京 21:43，在窗口内独立来源 3 家

TPU 8tx 与 TPU 8i Max（图片来源：Google Blog）

介绍

Google 于 11 月 9 日宣布扩展第八代 TPU 产品线，新增 TPU 8i Max 与 TPU 8tx，使一年内发布的第八代 TPU 系统达到四款（另两款为今年 4 月的 8t 与 8i）。官方称这是公司十多年来首次在一年内推出四款 TPU 系统。8i Max 面向超大上下文与单机架最高算力密度；8tx 面向安全与机密推理。

为什么重要

在黄仁勋风波与出口管制高压的同一周，Google 用「同一代硅片、两套新系统」继续铺开与英伟达竞争的云侧选择，尤其把机密计算和超长上下文写成独立机型。

要点
  • 8i Max：把两颗 TPU 8i 芯片封装在一起，官方称算力、SRAM 与 HBM 带宽均相对 8i 翻倍，并在原有机架占地内放入两倍硅片，强调单机架密度与大规模上下文。
  • 8tx：基于与 8t 相同的硅片，搭配 第 5 代 AMD EPYC 主机处理器，把安全做进硬件层，使敏感数据与模型权重在使用中仍保持隔离；官方称相对 TPU 8t 延迟最多降低 2 倍，并可用于私有数据微调、蒸馏与强化学习，而不必在集群间搬运敏感数据。
  • 软件栈：官方称 TorchTPU 可让 PyTorch 与 Hugging Face 模型在 TPU 上原生运行、无需改写代码；开源 TPU Sync 将 KV 传输延迟与首 token 时间降低 90% 以上。博文还称 TPU 已有近 100 家客户。
  • 未公布：两款新系统均未给出绝对规格、独立基准、价格与可用区域。4 月那对 8t / 8i「训练性能最高约 2.7 倍、推理性价比高约 80%」是相对上一代的旧口径，不要误当成今天的新测分。

OpenAI 上线 Control Room：研究侧模型负载可在 35 秒内停止输出

11-09 北京时间AIHOT 记官网动态 11-09 21:00；官方 X 帖北京 11-10 06:01，略出窗口独立来源 2 家

Control Room 介绍图（图片来源：OpenAI）

介绍

OpenAI 发布 Control Room：一套集中追踪并快速停止其研究基础设施中模型工作负载的系统，覆盖训练采样、评估和数据处理等智能体推理任务。官方称，从收到停止指令到模型无法继续产出，上限是 35 秒（来自授权缓存层），并已部署于研究基础设施。系统采用 fail-closed 设计：Control Room 服务宕机或被关闭时，所有推理请求都会被拒绝。

为什么重要

模型越强，研究集群里一次跑飞的代价越大。OpenAI 选择把「叫停权」做在推理引擎这一层，而不是指望各研究团队自己的任务代码守规矩。

要点
  • 机制：每个做智能体推理的研究任务必须关联一份已批准的 safety case，并向 Control Room 申请 job_id；推理引擎在满足每次采样前向 Control Room 询权，任务被标记停止后即拒绝继续输出。官方强调不把关键安全逻辑放在多变的 workload 代码里。
  • 35 秒与 fail-closed：35 秒是缓存带来的上限，官方写明正在把这一延迟往零推进。fail-closed 已覆盖所有前沿模型研究负载，其余研究负载将在「接下来几天」完成推广。对外的模型服务栈本身更集中，不在这次宣布的同一套系统里。
  • 与监测的关系：前沿强化学习任务配有监控模型；监控系统可直接通知 Control Room 停掉对应 job_id。官博提到近期一次与 DNS 相关的事件就是由监控捕获的。

千问办公 2.0 发布：把 Agent 带进工作群，定位 Team Agent

11-09 北京时间热榜 #10 · IT之家 16:15 · 官方更新日志同日独立来源 3 家

千问办公 2.0 开箱直播视觉（图片来源：InfoQ 转载的活动海报 / 千问办公）

介绍

钉钉系产品 千问办公 于 11 月 9 日发布 2.0，定位面向个人与组织协作的 Team Agent。IT之家援引钉钉官方消息称，这一版上线「协作」「人机共创」「资料空间」「自动任务」和「三端互联」，把 Agent 从个人助手扩展到可加入工作群的协作成员；官方客户端更新日志日期同为 2026 年 11 月 09 日，目前功能已在客户端全量上线。

为什么重要

多数办公 Agent 还停在「一个人跟模型聊天」。把数字员工放进真实的群、文档和待办里，是在赌下一阶段的工作单元是「人 + Agent 的共享空间」。

要点
  • 协作空间：可关联多个钉钉群聊、文档、AI 表格和 AI 听记，支持并行会话与任务指派；成员指派任务后，数字员工结合空间上下文梳理进展、总结共识并跟进待办。

百度发布 ERNIE Evolve 自动研究系统：在两项公开任务上超过此前公开最好成绩

11-09 北京时间文心官博条目 11-09独立来源 2 家

ERNIE Evolve 博文封面（图片来源：文心大模型官网）

介绍

百度文心团队发布自动研究系统 ERNIE Evolve：围绕明确目标与约束，持续提出研究方向、做实验、验证结果并积累经验。系统用双层循环组织工作——外层决定研究什么，内层把一个方向做深——并由 Director、Selector、Executor、Evaluator、Reviewer 分工。官博称，它在 NanoChat AutoResearch 与 NanoGPT Speedrun 两项公开任务上超过目前公开验证的最好结果，并已用于正在开发的 ERNIE-5.5-Flash 推理效率优化，改进获得生产级验证。

为什么重要

自动研究一旦能在真实仓库里改代码、跑评测并留下可复用经验，模型厂的迭代速度本身也会变成竞争变量。官方同时强调评测程序对智能体不可见，并设复核，以防刷榜或钻评测漏洞。

要点
  • 公开任务成绩（官方表，指标方向以官网为准）：NanoChat AutoResearch 验证集 BPB 0.8763（越低越好；社区公开最佳 0.8878）；NanoGPT Speedrun Track 1 达标训练时间 38.9 秒（社区最佳 39.9 秒）；Track 3 达标训练步数 2590（社区最佳 2690）。SOL-ExecBench 平均 SOL 分数 0.819，低于社区公开最佳 0.827，官博没有把这一项写成「超过最好成绩」。
  • 工作方式：Director 从经验库与知识库提出方向；Selector 在研究线内选起点和假设；Executor 在隔离环境改代码；Evaluator 是放在仓库外、对智能体不可见的固定评测；Reviewer 检查是否偏离方向或利用评测漏洞。
  • 落地：官博称在公开任务验证后，将系统用于 ERNIE-5.5-Flash 的推理效率优化，发现的改进得到生产级验证并带来「可观收益」。官网未给出具体加速百分比，本文不编造数字。
  • 交叉：文心官博（一手）+ AIHOT 11-10 日报收录。本期未读到第二家完整媒体长文，独立来源按官博 + AIHOT 计，并在状态表说明。
