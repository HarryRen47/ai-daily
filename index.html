OpenAI 与 Cisco 推出开源 Linux 运行时 Shirudo：用 eBPF 盾在不停机的情况下挡住漏洞路径

11-24 05:20 至 05:37 北京时间今日头条独立来源 3 家

OpenAI 与 Cisco 联合发布 Shirudo 的官方配图（图片来源：OpenAI og:image）

介绍

北京时间 11 月 24 日 05:20，Cisco 新闻稿与博客率先宣布与 OpenAI 共同推出开源项目 Shirudo（日语「盾」之意）；05:37，@OpenAI 发出主帖。官方介绍称，Shirudo 让安全团队测试并部署针对漏洞路径的临时盾，在服务继续运行的同时为正式补丁争取时间。盾在加载前需密码学签名与校验，并可借助 TPM 留下可验证记录。OpenAI 写道，在一次受控测试中，由 Codex 生成的盾为 Java 的 Base64 解码器增加输入检查，并附着到正在运行的 Elasticsearch 进程，从而挡住 Java4Shell 利用尝试且无需重启。Cisco 博客还提到该项目已对 Java4Shell 与一处 PHP 漏洞写出检测与拦截代码。代码与文档见 GitHub 与 docs.shirudo.dev。

为什么重要

补丁验证与全量部署往往以天或周计，而同一系统调用既可能是攻击路径也可能是正常请求。把「先挡住、再修补」做成开源、可签名的运行时，是安全团队与智能体协作的一次明确产品化；它不等于已经在生产环境大规模落地，也不等于可以替代正式补丁。

要点
  • Cisco 新闻稿署 2026-11-23T21:20:00Z（北京时间 11-24 05:20），OpenAI 主帖为 05:37（21,626 赞、13,595 次收藏）。
  • 核心机制是 eBPF：在运行中的 Linux 上观察或拦截特定操作，官方强调盾需签名验证，并可用 TPM 记录加载或卸载。
  • OpenAI 举例：Codex 生成的盾在受控测试中挡住针对运行中 Elasticsearch 的 Java4Shell 利用，且服务无需重启。
  • 项目开源，GitHub 为 shirudo-dev/shirudo；安全团队仍掌控是否把盾从观测升格为拦截，正式补丁到位后应退役临时盾。

METR：OpenAI 预训练损失自 2026 年初以来的下降速度约为 2022–2025 年的 7 倍

11-24 16:00 北京时间主线独立来源 2 家

METR 绘制的预训练损失下降曲线（图片来源：METR 博文配图）

介绍
